작성일: 2026-09-02
버전: v0.1 (초안)

## 1. 프로젝트 개요

### 1.1 한 줄 정의
LH·SH가 쏟아내는 공공임대주택 모집공고를 자동으로 수집하고, 내가 등록한 조건(나이·소득·자산·지역 등)에 맞는 공고만 골라 **카카오톡으로 알려주는 개인용 봇**.

### 1.2 해결하려는 문제
- 공고가 언제 뜰지 예측이 안 되고, 물 수 있는 접수 기간이 **3일 이내**로 매우 짧다
- LH청약플러스 / SH인터넷청약시스템 / 마이홈포털 / 서울주거포털 등 채널이 분산되어 있다
- 공고문 PDF가 수십 페이지라 내가 자격이 되는지 판단하는 데 시간이 오래 걸린다
- 결과적으로 "있었으면 넣었을 공고"를 놓친다

### 1.3 성공 기준 (MVP)
| 지표 | 목표 |
|---|---|
| 공고 탐지 지연 | 게시 후 1시간 이내 알림 |
| 누락률 | 대상 적합 공고 누락 0건 |
| 오탐(관련 없는 공고 알림) | 20% 이하 |
| 접수 마감 리마인드 | D-3, D-1, 마감일 정시 발송 성공률 100% |

### 1.4 범위 (Scope)
**포함**
- LH / SH 임대주택 모집공고 수집
- 사용자 조건 기반 1차 필터링
- 카카오톡 알림 (신규 공고 / 접수 임박 리마인드)
- 공고문 원문 링크 제공

**제외 (v1 이후 고려)**
- 자동 청약 신청 (불가 → 본인인증 필요, 시도하지 말 것)
- 당첨 확률 예측
- GH(경기)·iH(인천) 등 타 지방공사 (v2 확장)
- 다중 사용자 지원 (본인용 단일 사용자로 시작)

### 2.2 비기능 요구사항
- **비용**: 월 1만 원 이내 (가급적 무료 티어)
- **운영 부담**: 서버 관리 없이 돌아가야 함 (서버리스 또는 GitHub Actions)
- **장애 내성**: 수집 실패 시 재시도, 3회 연속 실패하면 나에게 에러 알림
- **관측성**: 실행 로그가 남고, 마지막 성공 시각을 확인할 수 있어야 함
- **예의**: 크롤링 시 요청 간격 1초 이상, User-Agent 명시, robots.txt 준수

## 3. 데이터 소스 분석

### 3.1 LH → 크롤링 채택 (오픈API 대신)

~~공공데이터포털(data.go.kr) 오픈API~~ 는 Phase 0에서 기각. API 상품(엔드포인트)마다 활용신청을 따로 해야 해서 개인 프로젝트치고 번거롭고, 실측해보니 **크롤링이 API보다 얻는 정보가 더 많고 접근도 쉬움**.

| 대상 | URL | 방식 |
|---|---|---|
| 임대주택 공고문 목록 | `apply.lh.or.kr/lhapply/apply/wt/wrtanc/selectWrtancList.do?mi=1026` | GET, 정적 HTML |
| 첨부파일 목록 | `apply.lh.or.kr/lhapply/wt/wrtanc/wrtFileDownl.do` | POST, JSON 응답 |
| 첨부파일(PDF) 다운로드 | `apply.lh.or.kr/lhapply/lhFile.do?fileid={id}` | GET, 인증/차단 없음 |

- 목록 페이지 표에 **유형·지역·공고일·마감일·상태**가 이미 다 있어 F-05/F-06을 상세 페이지 없이 처리 가능.
- "상세보기" 클릭은 NetFunnel(공공기관 트래픽 제어) 게이트를 거치므로 자동화 대상에서 제외. 목록+PDF만으로 충분해 굳이 뚫을 필요 없음.
- PDF는 `pdfplumber`로 텍스트 추출 검증 완료 (43페이지 문서, 정상 추출).
- 상세 실측 기록: `research/FINDINGS.md`.

### 3.2 SH → 오픈API 없음, 크롤링 필요

| 채널 | URL | 비고 |
|---|---|---|
| SH 인터넷청약시스템 (주택임대 공고) | `i-sh.co.kr/app/lay2/program/S48T1581C563/www/brd/m_247/list.do?multi_itm_seq=2` | **핵심** 게시판 |
| SH 메인 청약공고 | `i-sh.co.kr/main/index.do` | 보조 |
| 서울주거포털 | `housing.seoul.go.kr/site/main/sh/publicLease/07/list` | 교차검증용 |

- 정적 HTML 게시판 → `requests` + `BeautifulSoup`으로 충분할 가능성 높음
- JS 렌더링이면 Playwright로 전환
- 게시판 목록에서 얻을 것: 제목, 게시일, 상세 페이지 URL, 첨부 PDF URL

### 3.3 보조 소스
- 마이홈포털 (`myhome.go.kr`) — 전국 공고 통합, 공공데이터 개방 페이지 확인 가치 있음
- 서울시 청년안심주택 (`soco.seoul.go.kr`) — v2 확장 대상

### 3.4 수집 전략 요약
```
LH  → 목록 페이지 크롤링(유형·지역·공고일·마감일 확보) + 필요 시 PDF 다운로드/파싱
SH  → 게시판 크롤링(POST 상세) + 상세 페이지 인라인 텍스트가 1차 소스, PDF는 보완
공통 → 둘 다 오픈API 불필요. PDF는 원문 링크 저장 + 텍스트 추출 후 LLM으로 구조화(Phase 4)
```

### 4.3 기술 스택
| 영역 | 선택 | 이유 |
|---|---|---|

| HTTP | `httpx` | 동기/비동기 모두 지원 |
| 파싱 | `BeautifulSoup4` + `lxml` | 정적 HTML |

| PDF | `pdfplumber` | 표 추출 강함 |

| 검증 | `pydantic` | 스키마 강제 |
| 스케줄 | GitHub Actions `schedule` | 무료, 서버 불필요 |
| 시크릿 | GitHub Secrets / `.env` | |
| 테스트 | `pytest` + 저장된 fixture HTML/JSON | 실서비스 호출 없이 테스트 |

## 6. 매칭 엔진 설계

### 6.1 기본 원칙
**절대 "부적합"으로 조용히 버리지 않는다.** 공고문 해석이 애매한 경우가 많으므로, 확실한 것만 걸러내고 나머지는 사람이 판단하게 둔다.

### 6.2 3단계 판정
| 판정 | 조건 | 알림 |
|---|---|---|
| `MATCH` | 모든 하드 조건 통과 | 즉시 발송 (강조) |
| `NEEDS_REVIEW` | 조건 추출 실패 또는 경계값 | 발송 (확인 필요 표시) |
| `NO_MATCH` | 하드 조건 명확히 위반 | 발송 안 함, DB에만 기록 |

### 6.3 하드 필터 (탈락 조건)
```
1. 주택 유형이 interests.housing_types에 없음        → NO_MATCH
2. 지역이 preferred_districts / residence와 무관       → NO_MATCH
3. 나이가 age_min~age_max 범위 밖 (명확할 때만)         → NO_MATCH
4. 혼인 요건 불일치 (미혼 요구 & 기혼 등)               → NO_MATCH
5. 접수 종료일이 이미 지남                              → NO_MATCH
6. 보증금/월세가 상한 초과 (정보 있을 때만)              → NO_MATCH
7. 판정에 필요한 필드가 없음                             → NEEDS_REVIEW
```

### 6.4 소프트 스코어 (참고 정보로만 표시)
```
+ 소득 여유율      = (기준액 - 내 소득) / 기준액
+ 지역 거주기간     → 가산 있을 시 점수
+ 청약통장 매수     → 가산 있을 시 점수
+ 선호 지역 일치도
+ 세대원수 (1/2/3인 조건 대조)
```
점수는 **당첨 확률 예측이 아니라 "우선순위 힌트"**로만 표기한다. 과신하지 않도록 메시지에 "참고용" 명시.

### 6.5 소득 기준 계산 원칙
도시근로자 가구원수별 월평균소득 기준은 **매년 갱신**되므로 코드에 하드코딩하지 말고 `data/income_standards.yaml`로 분리한다.
```yaml
# 2026년 기준 (매년 확인 후 갱신 — 출처: 통계청/공고문)
year: 2026
verified_at: 2026-09-02
source: "SH/LH 모집공고문"
household:
  1: { krw: 4310000, note: "예시값 — 실제 공고문으로 검증 필요" }
  2: { krw: 6020000 }
  3: { krw: null }
```
> 이 값들은 반드시 **실제 공고문에서 확인 후 채울 것**. 추정치로 필터링하면 오탈락이 발생한다.

## 7. 알림 설계

### 7.1 채널 선택: 카카오톡 "나에게 보내기"

| 방식 | 가능 여부 | 비고 |
|---|---|---|
| **나에게 보내기** (`talk_message`) | 가능, 개인 개발자 가능, 무료 | **채택** |
| 친구에게 보내기 | 가능하지만 카카오톡 심사 권한 재심사 필요 | 본인용이라 불필요 |
| 알림톡 | 가능하지만 사업자등록·비즈채널·유료 | 과함 |

**구현 흐름**
1. Kakao Developers에서 앱 생성
2. 카카오 로그인 활성화 + Redirect URI 등록 (`http://127.0.0.1:8765/callback`)
3. 동의항목에서 `talk_message` (카카오톡 메시지 전송) 활성화
4. 최초 1회 로컬에서 OAuth 인증 → `access_token` + **`refresh_token`** 획득
5. `refresh_token`을 GitHub Secrets에 저장, 발송 전 access_token 갱신
6. `POST https://kapi.kakao.com/v2/api/talk/memo/default/send`

**핵심 주의점**: access_token은 수명이 짧다(수 시간). refresh_token으로 자동 갱신하는 로직이 필수. refresh_token도 만료될 수 있으니, 갱신 실패 시 **이메일 등 백업 채널로 "재인증 필요" 알림**을 보내야 한다.

### 7.2 백업 채널 (권장)
카카오 토큰이 죽으면 알림 전체가 침묵한다. 이중화 필수:
- 1차: 카카오톡
- 2차: 이메일 (SMTP) 또는 Discord/Slack Webhook
- 카카오 발송 실패 시 자동으로 2차 채널 사용

## 12. Claude Code 사용 가이드

### 12.1 큰 원칙
1. **Phase 단위로 진행한다.** 한 번에 전체를 만들라고 하면 검증 불가능한 코드가 나온다.
2. **Phase 0(실측)을 절대 건너뛰지 않는다.** 실제 응답을 보기 전 설계는 추측이다.
3. **매 Phase 끝에 "직접 실행해서 결과 보여줘"를 요구한다.** 돌지 않는 코드가 커밋되는 걸 막는다.
4. **테스트 fixture는 Phase 0에서 받은 실제 데이터로 만든다.**

### 12.2 리포지토리에 넣을 CLAUDE.md 초안

아래 내용을 프로젝트 루트의 `CLAUDE.md`로 저장하면 Claude Code가 매번 참조한다.

````markdown
# 프로젝트: LH/SH 공공임대 공고 알림 봇

## 목적
LH·SH 임대주택 모집공고를 수집해, 내 조건에 맞는 공고를 카카오톡으로 알린다.
접수 마감 전 리마인드도 보낸다. 개인용 단일 사용자 도구.

## 설계서
전체 설계는 `docs/설계서.md` 참조. 구조를 바꾸려면 먼저 설계서를 갱신할 것.

## 기술 스택
Python 3.11+ / httpx / BeautifulSoup4 / pdfplumber / pydantic / SQLite / pytest
스케줄: GitHub Actions

## 절대 규칙
1. 네트워크 호출은 `tests/fixtures/`에 저장된 응답으로 테스트한다. 테스트가 실제 사이트를 때리면 안 된다.
2. 파싱 실패와 "결과 없음"을 구분한다. 셀렉터가 안 맞으면 예외를 던지고, 빈 리스트를 반환하지 않는다.
3. 자격 판단 애매하면 NO_MATCH가 아니라 NEEDS_REVIEW다. 오탈락 > 오알림이라는 판단을 항상 지킨다.
4. `profile.yaml`, `.env`는 절대 커밋하지 않는다. 소득·자산 정보가 들어 있다.
5. 로그에 소득·자산 금액을 출력하지 않는다.
6. 소득 기준 금액을 코드에 하드코딩하지 않고 `data/income_standards.yaml`에서 읽는다.
7. 자동 청약 신청 기능을 구현하지 않는다.
8. 크롤링 시 요청 간격 최소 1초, User-Agent 명시.

## 작업 방식
- 새 기능은 먼저 실패하는 테스트를 만들고 구현한다.
- 커밋은 논리 단위로 쪼갠다. Phase 하나를 한 커밋으로 만들지 않는다.
- 외부 사이트 구조에 의존하는 셀렉터/필드명은 `src/config.py`에 모은다.
- 작업 후 반드시 `pytest`를 실행하고 결과를 보고한다.

## 현재 Phase
Phase 0 — 데이터 소스 실측 진행 중
````
