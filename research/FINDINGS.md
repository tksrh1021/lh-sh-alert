# Phase 0 실측 결과

작성일: 2026-09-02
상태: SH 실측 완료, LH는 API 키 발급 대기 중

## SH 인터넷청약시스템 (완료)

### 1. 목록 페이지 (`list.do`)
- 정적 HTML, `requests`/`httpx`만으로 충분. JS 렌더링 불필요.
- 표 구조: `<table>` 안에 `<tr>` 15개 (헤더 1 + 데이터 14, 페이지당).
- 컬럼: 번호(글번호) / 제목(+NEW 뱃지) / 부서명 / 조회수. **날짜 컬럼은 목록에 없음** — 설계서 가정과 다름. 날짜는 상세 페이지에서만 확인 가능.
- 총 게시글 수(`총 1676건 [1/168페이지]`)가 페이지 상단에 있어 페이지네이션 가능.

### 2. 상세 페이지로 가는 방식 — **설계서 가정과 다름**
- 목록의 제목 링크는 `href="#"`, 실제로는 `onclick="getDetailView('309497')"` JS 호출.
- `getDetailView(seq)`는 `<form name="mainform" action="./list.do" method="post">`의 hidden field(`seq`, `multi_itm_seq=2`, `page`)를 채운 뒤 `action`을 `view.do`로 바꿔 **POST 제출**한다.
- 즉 단순 GET 링크 크롤링이 안 되고, `httpx.post(view.do, data={seq, multi_itm_seq: "2", page: "1"})` 형태로 재현해야 함.
- 검증: seq=309467, 309497 두 건 모두 정상 동작 확인 (`research/samples/sh_detail_*.html`).

### 3. 공고 본문 — **설계서 가정보다 훨씬 좋음**
- 상세 페이지 자체에 공고문 전체가 **인라인 HTML 텍스트**로 들어있음 (HWP→HTML 변환본으로 추정).
- `청약신청 일정`, `서류심사대상자 발표`, `자격요건` 등 섹션이 `■`, `○`, `※` 불릿과 함께 텍스트로 존재 → **BeautifulSoup의 `get_text()`만으로 접수기간·서류심사일 추출 가능**.
- 실제 추출 예 (seq=309467, 제51차 장기전세주택):
  ```
  ■ 청약신청 일정(인터넷 및 방문)
  ○ [1순위] 2026. 9. 14.(월) 10:00 ~ 2026. 9. 15.(화) 17:00
  ○ [2순위] 2026. 9. 16.(수) 10:00 ~ 17:00
  ○ [3·4순위] 2026. 9. 17.(목) 10:00 ~ 17:00
  ■ 서류심사대상자 발표: 2026. 10. 14.(수) 16:00 이후
  ```
- **설계 변경 포인트**: 설계서 3.4/4.2는 "SH는 PDF 파싱 필요"를 전제했는데, 실제로는 **PDF 없이 상세 페이지 HTML만으로 F-05(유형·지역·접수일자 추출)와 F-09(소득·자산 기준 추출)의 상당 부분을 처리할 수 있다.** PDF는 서식(붙임 서류)이나 표 위주 공고에서 보완용으로만 필요할 가능성.
- 단, 텍스트가 `<span>` 단위로 글자/스타일별로 잘게 쪼개져 있어 `get_text()`로 합친 뒤 정규식으로 재조합해야 함 (공백/줄바꿈 정규화 필요).

### 4. 첨부파일(PDF) 접근 — 예상보다 까다로움
- 첨부 다운로드 버튼은 `onclick="existFile('0')"` — **Innorix**(국내 대형 파일 다운로드 플러그인/에이전트) 기반으로 추정, 일반 HTTP GET으로 파일을 못 받음.
- 대신 "미리보기" 링크가 있음: `/app/com/util/htmlConverter.do?brd_id=...&seq=...&data_tp=A&file_seq=1`
  - 하지만 이 URL은 정적 HTML이 아니라 **Synap Document Viewer**(JS SPA, PDF를 페이지별로 렌더링)를 반환. 서버사이드 요청만으로는 본문 텍스트를 못 뽑음 → Playwright로 렌더링하거나 Synap 내부 API(문서 텍스트/좌표 JSON)를 역공학해야 함.
- **결론**: 상세 페이지 본문 텍스트로 충분한 공고는 PDF를 아예 안 열어도 됨. PDF가 꼭 필요한 경우(본문에 없는 세부 표 등)만 Phase 4에서 Playwright 경로를 검토.

### 5. 예의/차단 관련
- User-Agent 커스텀 값으로도 정상 응답, 별도 차단/캡차 없음 (단발 요청 기준). 반복 요청 시 간격 유지 원칙은 그대로 지킬 것.

## LH 청약플러스 크롤링 (완료) — **오픈API 대신 채택**

data.go.kr는 API 상품(엔드포인트)마다 개별 활용신청이 필요해 개인 프로젝트치고 번거로움.
"크롤링이 더 쉽지 않은가"라는 질문으로 실측해본 결과, **크롤링이 API보다 확실히 낫다는 결론.**

### 1. 목록 페이지 — 정적 HTML, GET만으로 충분
- `https://apply.lh.or.kr/lhapply/apply/wt/wrtanc/selectWrtancList.do?mi=1026` (임대주택 공고문 목록)
- `<table>` row에서 바로 파싱 가능한 컬럼: 번호 / **주택유형**(행복주택·영구임대·국민임대 등) / 제목 / **지역**(시도) / 첨부파일여부 / **공고일** / **마감일** / **상태**(공고중/정정공고중/접수마감) / 조회수
- **API로 확인하려던 것(접수 시작/종료일, 유형, 지역)이 이미 목록 페이지에 다 있음.** 상세 페이지 진입 없이 F-05/F-06 매칭이 가능.

### 2. "상세보기" — NetFunnel 대기열 게이트 있음 (건드릴 필요 없음)
- 목록의 제목 클릭(`wrtancInfoBtn`)은 NetFunnel(공공기관 트래픽 제어/차단 시스템) 티켓 발급 후 폼 제출하는 구조.
- `response.status`가 `Block`/`IpBlock`(반복 요청 시 차단)까지 있는 걸 보면 자동화 크롤링 대상으로는 부적합.
- **하지만 목록+PDF만으로 필요한 정보를 다 얻을 수 있어 상세보기 자체를 스킵하면 그만.** NetFunnel을 우회/자동화하려는 시도 자체가 불필요.

### 3. 첨부파일(PDF) — NetFunnel 없이 깔끔하게 접근 가능
- 첨부파일 목록: `POST /lhapply/wt/wrtanc/wrtFileDownl.do` (data: uppAisTpCd1/aisTpCd1/ccrCnntSysDsCd1/lsSst1/panId1, 목록 행의 data-id 속성에서 추출) → JSON으로 파일명/`cmnAhflSn`(파일ID) 반환. NetFunnel 없음.
- PDF 다운로드: `GET /lhapply/lhFile.do?fileid={cmnAhflSn}` — 인증/차단 없는 단순 GET. 실제로 "진천성석외2행복주택..." 공고문 PDF(43페이지, 1.5MB) 다운로드 성공.
- `pdfplumber`로 텍스트 추출 확인: 건설위치, 신청자격 등 본문이 정상적으로 뽑힘.

### 결론 — 설계 변경
- **LH 오픈API(`lhLeaseNoticeInfo1` 등)는 채택하지 않는다.** `DATA_GO_KR_KEY` 불필요, data.go.kr 활용신청 절차 자체를 스킵.
- LH 수집 파이프라인: 목록 페이지 크롤링(GET) → 필요 시 첨부파일 AJAX(POST) → PDF 다운로드(GET) → pdfplumber 텍스트 추출. SH와 마찬가지로 순수 크롤링 기반으로 통일.
- LH가 SH보다 오히려 쉬움: 목록에 마감일까지 있고, PDF가 Innorix/Synap 같은 방해 없이 바로 받아짐 (SH는 PDF 접근이 더 까다로웠음).

## 설계서 수정 사항 (반영 완료)

1. **3.1**: LH 오픈API 섹션 삭제, 크롤링으로 대체.
2. **4.2 모듈 구조**: `lh_api.py` 삭제, `lh_crawler.py`로 통합. `sh_crawler.py`는 `httpx.post`로 `view.do` 호출 (GET 아님).
3. **3.4 / Phase 4**: SH·LH 모두 "PDF 파싱 필수"가 아니라 "목록/상세 페이지 텍스트가 1차 소스, PDF는 보완"으로 변경. SH는 상세 페이지 인라인 HTML, LH는 목록 페이지 자체가 1차 소스.
4. **.env**: `DATA_GO_KR_KEY` 불필요 (제거 또는 선택값으로 격하).
